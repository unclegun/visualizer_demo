Why this reframing matters

The previous identity implied one chart demo, while the repository already contained UI docs, reusable snippets, and Razor implementation examples. Pattern-first organization gives teams a stable way to find and apply guidance.

Architecture philosophy taught here

Razor Pages handles routing and handlers, partials own fragment markup, HTMX handles transport and swap behavior, Bootstrap provides visual primitives, and focused JavaScript fills only the interaction gaps.

New technical showcase

Runtime browser state as CSS input

The new prop-for-that page shows how a static Razor-friendly site can expose pointer, visibility, form state, range values, and sampled media color to CSS variables, then build polished reactive effects from those values.

Why this page belongs here

It reinforces the repo’s architecture stance: Razor and HTMX can keep server concerns simple while CSS handles a surprising amount of reactivity once small runtime facts are exposed cleanly.
