What changes on October 1 for developers working in Azure DevOps, TFVC, two-week sprints, lead review, and UAT.

Daily Scrum prompts

  • Which item moved since yesterday?
  • What is the next state?
  • What threatens the Sprint Goal?
  • Who needs to collaborate today?
  • What should be discussed after standup?

Before calling work Done

  • Acceptance criteria are satisfied.
  • Code is complete and builds.
  • Work item and TFVC check-in are associated.
  • Lead review is complete.
  • Required validation and UAT are complete.
  • Board status is accurate.

Team rules

  • If meaningful work is happening, represent it on Azure Boards.
  • Story points estimate team size and uncertainty; they are not individual productivity scores.
  • Urgent sustainment work is visible and changes the forecast when it consumes capacity.
  • Design review, code review, UAT, and release controls remain part of the workflow.
  • Unit testing and CI are future maturity goals, not current gates we pretend to have.

When something changes

SituationFirst response
Work is bigger than expectedSplit it, clarify it, or adapt the forecast.
Production issue arrivesCreate/locate the work item and make the capacity tradeoff visible.
Dependency blocks progressMark the blocker, name an owner, and coordinate a next step.
Customer asks for new workCapture and prioritize it; do not silently add it to the sprint.
UAT rejects the itemKeep it out of Done and record the gap for replanning.
Remember: The goal is not to make every day predictable. The goal is to make work, quality, and tradeoffs visible early enough for the team to adapt.
