Pattern: HTMX Table Refresh

Row actions post with hx-post and refresh only a row or table region.

Why use this in ASP.NET Core Razor Pages

Avoid expensive full-page reloads while keeping update logic in normal Razor handlers.

How it works

Action buttons post identifiers, handler executes command, and returns either one row fragment or a refreshed tbody partial.

Copy-paste markup snippet

<button hx-post="/Users?handler=Approve&id=@row.Id"
        hx-target="#row-@row.Id"
        hx-swap="outerHTML">
  Approve
</button>

<div id="status" hx-swap-oob="true">User approved</div>

Razor Pages handler example

public async Task<PartialViewResult> OnPostApproveAsync(int id)
{
    await _users.ApproveAsync(id);
    var row = await _users.GetRowVmAsync(id);
    return Partial("_UserRow", row);
}

Partial view example

@model UserRowVm
<tr id="row-@Model.Id">
  <td>@Model.Name</td>
  <td>@Model.Status</td>
  <td>...</td>
</tr>

Notes, tradeoffs, and best uses

  • Refresh one row for idempotent row updates; refresh tbody for recalculated ordering.
  • Use hx-swap-oob for toast/status regions.
  • Keep action handlers explicit and auditable.
Row refresh vs table refresh
  • Row refresh: use when only one row status changes.
  • Tbody refresh: use when sort order, filters, or counts change.
  • Use out-of-band swaps for global notices and badge counters.
Tbody refresh snippet
<button hx-post="/Users?handler=BulkApprove"

  Approve Selected

Handler with OOB status
public async Task<PartialViewResult> OnPostApproveAsync(int id)
{
    await _users.ApproveAsync(id);
    var vm = await _users.GetRowVmAsync(id);
    Response.Headers["HX-Trigger"] = "status-updated";
    return Partial("_UserRow", vm);
}
OOB status fragment
<div id="globalStatus" hx-swap-oob="innerHTML">
  User approved at @DateTime.UtcNow.ToString("HH:mm:ss")
</div>

Keep global feedback outside table markup so layout remains stable.
