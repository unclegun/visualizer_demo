Pattern: DataTable + Modal

Searchable list and focused modal editing pattern that stays explicit in Razor Pages while minimizing repetitive markup and JavaScript.

Why this is useful in Razor Pages

Razor handlers remain clear for list loading and update actions, while partial views keep modal forms concrete and maintainable.

Architecture

Use one table partial, one modal partial, and thin handlers:

public async Task<PartialViewResult> OnGetEditUserAsync(int id)
{
    var vm = await _users.GetEditModelAsync(id);
    return Partial("_EditUserModal", vm);
}
Tradeoffs and scope
  • Client-side paging is simple for v1 and modest datasets.
  • Server-side processing can be added later without discarding the modal contract.
  • Keep edit forms explicit rather than reflection-generated.

Razor Pages mapping

Route and handler ownership stays with Razor Pages. Modals and table fragments remain regular partial views.

<button class="btn btn-sm btn-outline-primary"
        hx-get="/Users?handler=EditUser&id=42"
        hx-target="#modalBody"
        hx-trigger="click">
  Edit
</button>
How it works in production
  1. Initial page load renders table data from PageModel.
  2. Row action requests edit partial into a modal target.
  3. Form posts to page handler with anti-forgery token.
  4. Validation failures return the same partial with errors.
  5. Successful save returns either 204 or refreshed row/table fragment.

Save Handler Example
public async Task<IActionResult> OnPostSaveUserAsync(EditUserVm input)
{
    if (!ModelState.IsValid)
        return Partial("_UserEditForm", input);

    await _users.UpdateAsync(input);
    var row = await _users.GetRowVmAsync(input.Id);
    return Partial("_UserRow", row);
}
Modal Form Markup
<form hx-post="/Users?handler=SaveUser"
      hx-target="#row-@Model.Id"
      hx-swap="outerHTML">
  @Html.AntiForgeryToken()
  <input asp-for="Email" class="form-control" />
  <span asp-validation-for="Email" class="text-danger"></span>
  <button class="btn btn-primary" type="submit">Save</button>
</form>

Additional implementation notes

  • Use explicit DTO/view models for edit flows to avoid overposting.
  • Include concurrency tokens for multi-user admin screens.
  • Use a single shared modal shell in layout and load different bodies by handler.
  • Keep DataTable plugin setup in one JS module and call it once per page load.
