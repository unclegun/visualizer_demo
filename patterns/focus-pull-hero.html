Pattern Category: Advanced Hero Background

Focus-Pull / Rack-Focus Hero Background

What it is: a background image rendered in layered depth — blurred base + masked sharp focus regions — crossfading between areas to simulate a camera changing focus. Problem solved: static hero images that fail to communicate scientific complexity or premium craft.

A. JS-Animated

Rack-Focus Hero — Live Demo

Focus region: α-Helix Cluster

Molecular Strand Architecture

The lens shifts focus across protein domains — a static scientific image made to feel alive through depth and deliberate attention, without distracting from primary content.

The camera shifts focus to a new region every few seconds. Click Pause motion to freeze the effect, or Debug to overlay the focus region boundaries.

B. CSS-Only

Simplified CSS Animation — Zero JavaScript

CSS-only variant

Zero-JS Rack Focus

Two fixed focus regions crossfade using only CSS @keyframes on opacity. No JavaScript required — suitable for teams with strict CSP policies or minimal JS constraints.

Mask positions are hard-coded in CSS. Tradeoff: cannot dynamically reposition focus or display labels.

C. Static Fallback

Reduced-Motion / No-Animation Fallback

Reduced-motion fallback

Static Background Mode

When prefers-reduced-motion: reduce is detected, the base blurred layer stays static. No animation, no crossfade — just a stable dark hero. All content remains legible.

Documentation

What this pattern solves

Scientific, biotech, and research product pages often have high-quality microscopy or visualization images that look flat or static in a hero. The focus-pull pattern makes a single image feel spatially rich and premium without adding motion that competes with the headline or calls to action.

When to use it

  • Biotech or pharma product landing pages
  • Data visualization or scientific analytics portals
  • Enterprise dashboards where one hero image must communicate depth
  • Any dark-themed page needing ambient motion without distraction

How the focus-pull effect works

1. Layer stack

Three image layers share the same background SVG/image. The bottom layer is blurred and darkened (out-of-focus world). Two focus layers sit above it, each masked to a different region.

2. CSS masking

Each focus layer uses a radial-gradient mask — sharp in the center of the ellipse, feathered to transparent at the edges. The JavaScript updates the mask position by setting mask-image directly on the element.

3. Crossfade loop

Focus A is held at full opacity while focus B is pre-positioned at the next mark. After a hold delay, a CSS transition: opacity fades A out while B fades in — a true rack-focus crossfade, never a moving spotlight.

Layer structure

  1. Base layer (.fph-base) — blurred, darkened, slow Ken Burns drift
  2. Focus layer A (.fph-focus-a) — sharp, elliptical mask, transitions opacity
  3. Focus layer B (.fph-focus-b) — sharp, elliptical mask, transitions opacity
  4. Overlay (.fph-overlay) — dark gradient for text readability
  5. Content (.fph-content) — headline, lead text, actions

Performance notes

  • All animation uses opacity and transform — GPU-composited, no layout reflow
  • Mask changes update only paint, not layout
  • The SVG background is inline-loaded by the browser once, then composited per layer without refetch
  • Ken Burns uses will-change: transform to promote the layer to its own compositor layer
  • The CSS-only variant removes all JavaScript overhead entirely
  • Avoid using a large raster image (PNG/JPEG) if the hero is large — SVG scales at zero cost

Accessibility notes

  • prefers-reduced-motion is checked in JS before starting the animation loop; the static fallback activates automatically
  • The global @media (prefers-reduced-motion) rule in base.css also disables CSS animations, covering the CSS-only variant
  • A visible Pause motion control is always present for users who prefer to stop the effect without a system-level setting
  • All decorative image layers use aria-hidden="true"
  • Text contrast meets WCAG AA — the dark overlay ensures a legible background regardless of image content
  • No information is conveyed through the animation; the hero text is independent of motion state

Razor Pages mapping

  • _Layout.cshtml — add <link> for focus-pull-hero.css and (optionally) the JS module <script type="module">
  • Views/Shared/_FocusPullHero.cshtml — the HTML layer stack partial, accepting model properties for image URL, title, lead, and button text
  • wwwroot/js/focus-pull-hero.js — copy assets/js/patterns/focus-pull-hero.js; adjust the import path for motion.js utilities or inline the prefersReducedMotion helper
  • wwwroot/css/focus-pull-hero.css — copy assets/css/patterns/focus-pull-hero.css into the shared CSS bundle or include as a scoped stylesheet

Tuning focus marks

Each entry in focusMarks defines where the camera "looks". Adjust these to match the interesting regions of your own background image.

JavaScript 
export const focusMarks = [
  // x, y  = center of the focus ellipse (% of the hero element)
  // w, h  = ellipse radii (% of hero width / height)
  // label = displayed in the eyebrow and debug overlay
  { id: "alpha", x: "22%", y: "44%", w: "44%", h: "54%", label: "α-Helix Cluster"  },
  { id: "beta",  x: "62%", y: "30%", w: "40%", h: "50%", label: "β-Sheet Network"   },
  { id: "gamma", x: "76%", y: "58%", w: "38%", h: "48%", label: "γ-Node Junction"  },
  { id: "delta", x: "44%", y: "58%", w: "36%", h: "46%", label: "δ-Bridge Cluster" },
];

// To override per-page:
animateFocusPull(document.querySelector("[data-focus-pull-hero]"), [
  { id: "left",  x: "20%", y: "50%", w: "38%", h: "52%", label: "Left region"  },
  { id: "right", x: "75%", y: "50%", w: "38%", h: "52%", label: "Right region" },
]);

Use the Debug button on the live demo to visualise region boundaries as dashed ellipses — adjust x/y/w/h until each ellipse encloses the feature you want in focus.

Replacing the background image

The image URL is set via the CSS custom property --fph-image on the hero element. Change it in the HTML without touching the CSS or JS:

HTML 
<!-- Replace the SVG with any image format -->
<div class="fph-hero"
     data-focus-pull-hero
     style="--fph-image: url('/images/my-background.jpg')">
  ...
</div>

<!-- Razor Pages equivalent -->
<div class="fph-hero"
     data-focus-pull-hero
     style="--fph-image: url('@Url.Content("~/images/my-background.jpg")')">
  ...
</div>

Use SVG for illustrations and icons (infinite resolution, no refetch cost). Use WebP/AVIF for photographic images. The dark overlay layer will mask poor contrast regardless of image content.

Copy-paste starter snippet

Minimal markup needed to get the JS-animated version running:

HTML 
<!-- 1. CSS -->
<link rel="stylesheet" href="/css/focus-pull-hero.css" />

<!-- 2. HTML -->
<div class="fph-hero"
     data-focus-pull-hero
     style="--fph-image: url('/img/molecular-hero.svg')"
     aria-label="Animated hero background">

  <!-- Controls -->
  <div class="fph-controls">
    <button class="fph-btn" data-fph-pause type="button" aria-pressed="false">Pause motion</button>
    <button class="fph-btn" data-fph-debug type="button" aria-pressed="false">Debug</button>
  </div>

  <!-- Image layers -->
  <div class="fph-layer fph-base"    data-fph-base    aria-hidden="true"></div>
  <div class="fph-layer fph-focus-a" data-fph-layer-a aria-hidden="true"></div>
  <div class="fph-layer fph-focus-b" data-fph-layer-b aria-hidden="true"></div>
  <div class="fph-debug-labels"      data-fph-debug-labels aria-hidden="true"></div>
  <div class="fph-overlay"           aria-hidden="true"></div>

  <!-- Content -->
  <div class="fph-content">
    <p class="fph-eyebrow">Focus region: <span data-fph-active-label></span></p>
    <h1 class="fph-title">Your headline</h1>
    <p class="fph-lead">Your lead text.</p>
  </div>
</div>

<!-- 3. JavaScript (ES module) -->
<script type="module">
  import { initializeFocusPullHeroDemo } from "/js/focus-pull-hero.js";
  initializeFocusPullHeroDemo();
</script>

A reusable partial that accepts model data for the image URL, headline, and lead text:

@* Views/Shared/_FocusPullHero.cshtml *@
@model FocusPullHeroModel

<div class="fph-hero"
     data-focus-pull-hero
     style="--fph-image: url('@Url.Content(Model.ImageUrl)')"
     aria-label="@Model.AriaLabel">

  <div class="fph-controls">
    <button class="fph-btn" data-fph-pause type="button" aria-pressed="false">Pause motion</button>
  </div>

  <div class="fph-layer fph-base"    data-fph-base    aria-hidden="true"></div>
  <div class="fph-layer fph-focus-a" data-fph-layer-a aria-hidden="true"></div>
  <div class="fph-layer fph-focus-b" data-fph-layer-b aria-hidden="true"></div>
  <div class="fph-debug-labels"      data-fph-debug-labels aria-hidden="true"></div>
  <div class="fph-overlay"           aria-hidden="true"></div>

  <div class="fph-content">
    @if (!string.IsNullOrEmpty(Model.Eyebrow))
    {
      <p class="fph-eyebrow mb-2">@Model.Eyebrow</p>
    }
    <h1 class="fph-title display-6 fw-bold mb-3">@Model.Title</h1>
    <p class="fph-lead mb-4">@Model.Lead</p>
    @if (Model.Actions != null)
    {
      <div class="d-flex flex-wrap gap-2">
        @foreach (var action in Model.Actions)
        {
          <a class="btn @action.CssClass" href="@action.Url">@action.Label</a>
        }
      </div>
    }
  </div>
</div>

How to disable motion

  • User-level: enable prefers-reduced-motion in OS settings — both CSS animations and JS loop are automatically disabled
  • Page-level: add data-fph-pause attribute to a button with initial aria-pressed="true" and the JS will start in the paused state
  • Global: to strip all motion permanently, use fph-static-hero class instead of the animated markup
  • CSS-only: override .fph-base { animation: none; } in your own stylesheet

When not to use this pattern

  • High-frequency CRUD screens where users need fast focus on controls
  • Accessibility-first pages where any background motion would be a distraction even for users without vestibular sensitivity
  • Pages that already have significant foreground animation (chart entrances, data transitions)
  • Mobile-only contexts with limited GPU bandwidth — test on target devices
