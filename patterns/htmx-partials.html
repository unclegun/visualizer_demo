Pattern: HTMX Partials

Search/filter input updates a target fragment with hx-get and minimal client JavaScript.

Why use this in ASP.NET Core Razor Pages

Handlers return fragment HTML cleanly, preserving Razor validation and view composition without SPA overhead.

How it works

Input events trigger a handler endpoint, the response partial replaces a target region, and loading states are driven by HTMX lifecycle classes.

Copy-paste markup snippet

<input name="q"
       hx-get="/Users?handler=Search"
       hx-target="#results"
       hx-trigger="keyup changed delay:300ms"
       hx-indicator="#loadingIndicator" />
<div id="loadingIndicator" class="htmx-indicator">Loading...</div>
<div id="results"><partial name="_UserRows" model="Model.Users" /></div>

Razor Pages handler example

public async Task<PartialViewResult> OnGetSearchAsync(string? q)
{
    var results = await _users.SearchAsync(q);
    return Partial("_UserRows", results);
}

Partial view example

@model IReadOnlyList<UserListItemVm>
@foreach (var user in Model)
{
    <div class="list-group-item">@user.DisplayName - @user.Role</div>
}

Notes, tradeoffs, and best uses

  • Best for list filtering, search results, and compact dashboard panels.
  • Avoid for high-frequency stateful interactions requiring client reconciliation.
  • Pair with pagination handlers for large datasets.
Implementation flow
  1. Page renders initial list and search input.
  2. Input keyup triggers hx-get to the page handler.
  3. Handler returns only list fragment partial.
  4. HTMX swaps target region and preserves rest of page state.
Handler with paging
public async Task<PartialViewResult> OnGetSearchAsync(string? q, int page = 1)
{
    var vm = await _users.SearchAsync(q, page, pageSize: 20);
    return Partial("_UserSearchResults", vm);
}

Add paging early so the same pattern scales without redesign.

No results partial
@if (!Model.Items.Any())
{
  <div class="alert alert-light border">No matches. Try a broader search.</div>
}
else
{
  @foreach (var user in Model.Items)
  {
    <div class="list-group-item">@user.DisplayName</div>
  }

Progressive enhancement fallback
<form method="get">
  <input name="q" class="form-control" />
  <button type="submit" class="btn btn-primary mt-2">Search</button>
</form>
